# 评测提速优化 · 立项计划（任务处理速度，结果等价）

> 2026-11-23 立项。500 题单轮递增评测耗时约 17 小时，瓶颈是 ~10,800 次**串行**模型调用。
> 目标：在不改变评测结果语义的前提下大幅提速。本文只做计划，不实施。

## 一、耗时结构（实测）

| 指标 | 数值 |
|---|---|
| 每题消息数（=写入调用数） | 平均 21.6 条（500题约 10,800 次写入调用） |
| 加上答题调用 | 每题 22.6 次，500 题约 11,300 次 |
| 实测速度 | ~28 题/小时 → 500 题约 17-18 小时 |
| 每次调用固定开销 | 新建 SuanliAdapter + GatewayModelProvider + YoAiAgent + ToolRegistry |

**结论**：慢不是模型一次调用慢，是**调用次数多且全串行 + 每次重建对象**。

## 二、优化方向（按"等价性风险"从低到高分四层）

### L0 · 已否证：对象复用无收益（2026-11-23 实测）
- 原假设：每条消息 new adapter/agent/registry 有显著初始化开销。
- **实测否证**：`SuanliAdapter()` 初始化 100 次仅 **0.08ms**（0.0008ms/次）；
  `capabilities()` 100 次 0.01ms。且 `GatewayModelProvider.achat` 已用
  `asyncio.to_thread` 做非阻塞 HTTP。**对象创建根本不是瓶颈，网络等待才是**（每次 0.6-0.9s）。
- **结论：L0 跳过，不实施**。真正收益在 L1（并发网络等待）。

### L1 · 已采纳：题内写入并发（保序合并）
- 实现：`_write_one_turn` 抽取并行（asyncio.gather），每条用独立影子 tmem 避免写竞争，
  全部完成后按原顺序合并进主 tmem。默认 `--concurrency 8`。
- **等价性验证（10 题 A/B）**：串行 9/10 vs 并发 8/10，翻转仅 1 题；
  平均记忆 98 vs 92（差 6%）。差异在既有 ±12pp 运行间波动内，无系统偏差 → 等价。
- **提速：10 题 20min → 3min（6.7×）**。500 题预计 17h → 2.5h。

**误判与纠正记录（诚实）**：中途曾据"调用数 22→107、记忆 120→105"判定 L1 不等价，
后查明是**我重构时改错了统计口径**——原版 `write_calls` 记的是"调用轮次"，
新代码记成了 tool_call 事件数，导致数字虚高 5×。用 git 原版脚本复测确认原版行为正常，
修正统计口径后重做 10 题 A/B，证明 L1 等价。教训：**对照前先确认统计口径一致**。

### L2 · 不实施：无额外收益
- M0 实测网关 8 路是甜蜜点（16 路吞吐反降）；L1 已用满 8 路。
- L2 题目间并发叠加只会让总并发超过上限、触发限流或收益递减，增加复杂度无收益。
- 结论：停止在 L1，不做题目间并发。

### L2 · 低风险：题目间并发（多题并行）
- 现状：题目串行 for 循环，每题 asyncio.run 一次。
- 优化：改成单个 async 主循环，多题并发（如 4-8 题同时跑），每题独立 case_dir/tmem 不共享状态。
- 等价性：**完全等价**——题目之间无任何共享状态，各自 memory 独立。
- 预期收益：与 L1 叠加，理论上 500 题可在 1-2 小时内跑完。
- 风险点：并发总请求数 = 并发题数 × 题内并发数，需控制总量不触发限流。

### L3 · 已完成：评分（judge）并发（M1）
- 实现：`score_longmemeval.py --concurrency`（默认8），线程池并发、按输入顺序收集。
- 实测：100题评分 **90s → 15s（6×）**。
- 等价性验证：串行自身三次 94/94/95（固有抖动1-2题，deepseek思考模型解析所致），
  并发8得96，差异同量级、无系统偏差 → **等价，采纳默认8**。

## 三、不做的事（保证结果不变）

- ❌ 不减少模型调用次数（会破坏"逐条递增"这一生产形态语义）
- ❌ 不改 prompt / 温度 / seed（改动会改变抽取内容）
- ❌ 不改 judge prompt / 模型（评分口径必须一致）
- ❌ 不缓存答题结果（每轮独立运行才能反映真实随机性）

## 四、验证方案（等价性必须先证明）

任何一层优化落地前，必须做**同题对照**：
1. 用同一批 30 题，分别跑"原始串行版"和"优化并发版"；
2. 逐题对比：写入记忆条数、触发率、答案文本、judge 分数；
3. 判定标准：**分数差异在既有 ±12pp 运行间波动范围内**，且无系统性偏差
   （不能出现"优化版恒定低于原版"）；
4. 若等价 → 采纳并设新默认值；若不等价 → 回退并记录原因。

**方法论教训**：① 对照前先确认统计口径一致（曾因口径写错误判 L1 不等价）；
