# 消息操作与附件能力设计（2026-11-26，已拍板：软删除+分支 / 文本抽取附件 / 本地导出分享）

目标：补齐常规 Agent 工作台的「附件 / 一键复制 / 撤回 / 编辑消息 / 分享 / 重新生成」，
先定归属与语义，再动代码。**归属判断：全部是 YoAi 侧 UI + runtime 能力，Core 零改动。**

**已拍板（2026-11-26）**
- 撤回/编辑：软删除 + 分支，不物理改写 Core 历史；
- 附件：文本类抽取进上下文 + 文件卡片；图片/二进制只做本地预览，不承诺视觉理解；
- 分享：导出本地 Markdown / HTML（不做公网链接）。

## 一、功能归属矩阵

| 功能 | 用户消息 | 智能体消息 | 语义 |
|---|---|---|---|
| 添加附件 | ✅ 专有 | ❌ | 发消息时携带本地文件；智能体侧对应能力是已有的「产物卡片 / 文件改动」，不叫附件 |
| 编辑消息 | ✅ 专有 | ❌ | 改自己的提问后从该点重发，形成分支；智能体回答不直接改写 |
| 撤回 | ✅ 专有 | ❌ | 撤回自己刚发的那条；智能体回答用「重新生成 / 停止」，不叫撤回 |
| 重新生成 | ❌ | ✅ 专有 | 针对某条智能体回答重跑同一提问 |
| 停止生成 | ❌ | ✅ 专有 | 终止正在进行的智能体任务（已有） |
| 复制 | ✅ | ✅ | 复制消息纯文本；代码块保留各自复制按钮 |
| 分享 | ✅ | ✅ | 导出单条或一段会话；发起者始终是人，智能体不主动外发 |
| 查看思考 / 过程 | ❌ | ✅ | 已有，保留 |

一句话口径：**用户专有＝附件、编辑提问、撤回提问；智能体专有＝重新生成、停止、思考/过程、产物；两者都有＝复制、分享。**

## 二、交互设计

### 输入区（聊天区底部）
- 回形针按钮 → 系统文件选择器（复用已装 `@tauri-apps/plugin-dialog`）；
- 选中的文件以 chip 显示在输入框上方，带 × 移除；
- 发送时把附件引用与抽取出的文本一起交给任务链；
- 当前网关是**文本模型**（`yai_multimodal=False`）：文本类附件可进上下文，
  图片/二进制只做文件卡片和本地预览，不承诺视觉理解。

### 消息动作条（hover 显示）
- 用户消息：`复制` / `编辑` / `撤回` / `分享`
- 智能体消息：`复制` / `重新生成` / `分享` / `查看思考`（已有）
- 运行中消息：`停止`（已有），不显示编辑/撤回

### 分享
- 范围：单条消息 / 当前会话最近 N 轮 / 整段会话；
- 形式：导出本地 `.md` / `.html`，或复制到剪贴板；
- 不做公网链接——没有后端托管，公开分享需要新服务，不在这次范围内。

## 三、数据与协议设计（协议 v1 追加，不破坏旧消息）

### 新增数据
- `AttachmentRef`：`id / name / size / mime / path / extracted_text / created_at`；
  文件落在 `<data_dir>/attachments/<session_id>/`，不外传、不自动执行。
- 消息扩展字段：`id / role / text / attachments[] / status / parent_id / branch`；
  老快照没有这些字段时前端按原样显示，不报错。

### 新增命令（前端 → runtime）
| 命令 | 用途 |
|---|---|
| `attachment.prepare` | 登记选中文件：复制进附件目录、抽取文本（大小/类型校验） |
| `attachment.remove` | 发送前移除尚未提交的附件 chip |
| `message.retract` | 按 `message_id` 撤回用户消息 |
| `message.edit` | 按 `message_id` + 新文本生成分支并重发 |
| `task.regenerate` | 按 `run_id` 重跑对应提问 |
| `share.export` | 按范围/格式导出 Markdown/HTML 或回剪贴板文本 |

### 新增消息（runtime → 前端）
`attachment.ready`、`message.updated`、`share.exported`；
错误阶段沿用 `error(stage=file|message|share)`。

## 四、撤回 / 编辑的关键语义（需拍板）

推荐方案：**软删除 + 分支，不物理改写 Core 历史**。

- 撤回：在 YoAi 侧动作表标记该消息 `retracted`，UI 隐藏并按该点截断模型上下文；
  原始记录留在本地审计日志里，可追溯但不进后续任务。
- 编辑：保留原消息，生成一条新分支；新提问从该点重新发给模型，旧分支仍可查看。
- 理由：Core 的公开内存 API 只有 `history/append_history/clear`，没有单点删除；
  直接 `clear()` 再重放会丢时间戳且不可逆，分支更安全，也符合「不在安全机制上开后门」。

备选（不推荐，除非明确要求）：原位覆盖式编辑/硬删除——需要重建会话历史，代价是不可恢复。

## 五、安全边界

- 附件只接受本地文件选择结果，不接受 `file://` / 远程 URL；
- 单文件与总量上限、类型白名单；文本抽取失败如实提示，不静默丢弃；
- 附件文件不自动执行、不自动上传到任何外部服务；
- 撤回/编辑只作用于当前会话，跨会话无效；
- 分享导出只写本地文件或剪贴板，不生成公网链接；
- 所有动作写审计日志，失败可见，不产生「假成功」。
