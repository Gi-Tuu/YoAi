# 生产问题：模型"说去查"却停住，要再问才返回（2026-11-24）

## 现象

当时的原话："我让他去查能不能调用工具，他说去查，然后就不返回内容了，我问了才告诉我结果。"

## 根因（复现确认）

不是 Core 循环提前结束，也不是桌面端丢事件——脚本与桌面 worker 都验证正常。
真正原因是**模型的间歇性行为 + Core 的合理默认冲突**：

1. 模型偶尔在第 1 轮只输出一句**行动承诺元话语**（"好的，我去查一下。"），
   **没有真的调工具**（工具模式下它本该直接给出 tool_calls）
2. Core 的 react 循环规则：`if not resp.tool_calls` → 纯文本即最终答案 → 发 `done`、结束
3. 用户看到的"结果"就是那句"我去查一下"，任务实际没执行
4. 用户再问一句 → 新的 astream → 这次模型才调工具、给出结果

复现（`bench/probe_continuation.py` 用脚本模型模拟"先过渡后执行"）：
```
模型被调用轮数=1
model_message: 好的，我去查一下能不能调用工具。
done: 好的，我去查一下能不能调用工具。   ← 工具轮根本没发生
```

这是**间歇性**的：真实讯飞在正常措辞下 5/5 都是第一轮直接调工具，只有特定条件
（复杂 prompt、模型状态波动）才踩坑。与项目里"模型自记随机性"是同类问题。

## 为什么不在 Core 改

- Core 的"纯文本 = 最终答案"是合理默认——改了会导致"你好"这类普通问答也卡住
- Core 的 system prompt 是内核硬编码，无扩展点；改内核跟不上 Core 更新
- 项目约定：内核可改但要能适应 Core 更新 → 优先在 YoAi 侧适配层解决

## 修复（`87e93f5`）

在 `GatewayModelProvider.achat`（YoAi 侧适配层，Core 升级天然兼容）：

- 检测到**纯文本 + 有工具 + 是过渡语**（窄正则：`我去查` / `让我看看` / `稍等` /
  `我来试试看` 等，且整句短、无实质内容）时：
  追加 `请直接调用工具执行，不要只描述你要做什么，然后给出最终结果。`
  **重试一次**（最多一次，防循环）
- 重试仍失败/仍是过渡语 → 返回原响应，不无限纠缠
- `reask_on_stall=False` 可关闭
- 正常回答/无工具场景**零额外请求**

验证：
- 过渡语 → re-ask → 工具调用 → 最终答案自动返回（模型请求 3 次，用户不用再问）
- 真实讯飞回归：正常对话 1-3 轮，零干扰
- 新增 `tests/test_gateway_continuation.py`，全量 212 passed

## 与相关问题的区别

| 问题 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 静默失败（前一个） | DSML 发出但无结果 | DIRECT 不给 schema 却给目录 | 工具优先路由 `YoAiRouter` |
| 本问题 | 说"去查"就停住 | 模型元话语被当最终答案 | 适配层 re-ask |

两者都是"模型行为 + Core 合理默认"的冲突，都在 YoAi 侧解决、不动内核。
