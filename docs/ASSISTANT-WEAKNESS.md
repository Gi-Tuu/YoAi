# assistant 类弱项 · 低温底座下的攻坚记录

> 2026-11-22。assistant 类（问"助手之前提到的内容"）是全项目唯一持续偏弱的题型：
> 低温最优配置下 48.2%，其它类 60-93%。用户要求攻坚，本文记录根因与三次尝试。

## 一、根因诊断（低温底座）

看失败题的记忆内容，**助手话已经在记忆里了**（speaker 字段工作正常），问题是：
- 题1（答案 "Nu, pogodi!"）：记忆有 4 条助手话，但**没记那个苏联动画片名**——实体漏记。
- 题2（答案 "Patagonia and Southwest Airlines"）：记忆只记了 Patagonia，
  **Southwest Airlines 完全没记**——助手话编号列表只记了第1项。

统计：29 个失败题中 **28 个助手话含大量专名、24 个含编号/多实体列举**。
根因高度集中：模型自记助手话时只记少数几个实体，漏掉答案需要的那个。
低温稳定了"认真模式"，但每次仍只记 13-16 条，覆盖不全。

## 二、三次尝试（低温底座，同 30 题 seed 20261121）

| 方案 | assistant 30题 | vs 基线 |
|---|---|---|
| 基线：低温 + 混合式记忆 | **60.0%** | — |
| 分段式（助手话独立预算） | 50.0% | -10pp |
| 增强 prompt（穷举+排除寒暄） | 26.7% | -33.3pp |
| **正则专名补充**（抓编号列表实体） | 50.0% | -10pp |

**全部失败，均低于基线。**

## 三、为什么专名补充也失败

正则成功抓到了 96 个专名（17 题触及，含 Southwest Airlines），但补的是
"助手提到 Southwest Airlines"这种**孤立事实**——没有上下文（哪家公司、以什么著称、
和另一家的关系）。检索到这条也答不出"哪两家公司"。

对比数字补充为什么有效："3 sisters" 本身就是完整答案，补进来直接可用。
专名是**关系的锚点而非答案本身**，需要连同上下文/关系一起记才有价值，
简单规则补充做不到（会引入大量无上下文噪音：修对1/弄坏4）。

## 四、结论（诚实）

- 低温底座下 assistant 48.2%（全量）已是当前最优，三种补助手话方案都不如默认。
- 根因不是"助手话没进记忆"（已进），也不是"模式随机"（低温已解决），
  而是**助手话里实体关系的抽取覆盖不足**——需要连同上下文的结构化抽取，
  简单提示/规则补丁无效。这是更深层的问题，需专门立项（类比 AMBRACE 的
  RELATIONSHIP/BIO 完整表述 + 逐字依据），不属于本轮能quick fix的范围。
