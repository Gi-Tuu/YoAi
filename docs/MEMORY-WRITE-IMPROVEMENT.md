# 记忆写入质量改造 · 借鉴 AMBRACE

> 2026-11-22。AMBRACE 项目有成熟的记忆层，考察有没有能用的。
> 本轮从其抽取 prompt 与兜底护栏中借鉴思路，落到 YoAi 的记忆写入。

## 一、AMBRACE 记忆层审查结论（只读探索）

AMBRACE 后端是 Python + SQLAlchemy + FastAPI，记忆层在 `backend/app/memory/`（约 70 模块），
是迭代了大量批次的成熟系统。与 YoAi 瓶颈（记忆写入质量）最相关的资产：

| 资产 | 路径 | 精华 |
|---|---|---|
| 抽取 prompt | `extractor.py:56-89` | 9 类分类 + 重要度(1-5) + 每条≤75字 + 相对时间转具体日期 + 禁止脑补/抄台词 + 逐条字面依据 |
| 正则兜底 | `response_parser.py:8-65` | 10 条正则抓名字/喜好/所在地等，带 title 证据锚点守卫 |
| 确定性兜底 | `fallback.py:1-15,222-285` | 三条硬约束：**内容不造句（逐字取自原话）**、严格胜出、改口不回灌旧值、周期不编日期 |
| 台词过滤 | `dialogue_filter.py:45-56` | 省略号/动作括号/口语复述拦截 |
| speaker 规则 | `speaker.py:33-61` | 推断词→前缀→批级回退 |

**关键判断**：AMBRACE 没有"自记条数不足"的直接解法，它的兜底只在"用户明确下令记"时动。
但它证明了：**纯规则/正则的确定性层是提升写入质量的有效手段，且必须逐字保留、不造句**。

## 二、YoAi 的瓶颈实证

失败案例（`8e91e7d9`，问"几个兄弟姐妹"，答案 4）：
- haystack 有 "I come from a family with 3 sisters" + 别处 "a brother"；
- 模型自记只记 3 条，把 "3 sisters" 摘成了前半句 demographics 废话；
- 数字藏在句子中段，被"取第一个分句"的截断规则漏掉 → 答 3 错。

**根因**：不是工具/检索问题，是**模型自记的提取位置偏误**——逐行取开头，漏句中数字。

## 三、落地改造（YoAi 内）

### 1. 数字事实正则补充层（`TemporalMemory.supplement_number_facts`）
- 借鉴 AMBRACE `response_parser.py`：正则抓"数字 + 名词"
  （sisters/brothers/pets/necklaces/miles/days... + 英文数词）；
- **逐字保留**原短语（如"3 sisters"），不造句、不换算——遵守 AMBRACE 护栏；
- **无条件叠加**：模型记了也跑（不同于 fallback 只在 0 条时接管）；
- 去重：已记过的不重复。
- `--num-supplement` 开关启用。

### 2. 增强抽取 prompt（`--prompt-style enhanced`，试验性）
- 借鉴 AMBRACE 分类清单：PEOPLE/NUMBERS/EVENTS/ITEMS/PREFERENCES/ASSISTANT；
- 数字专类 + 逐字保留 + 相对时间具体化 + 逐条穷举 + 排除寒暄。
- **实测发现**：模型仍无视"排除寒暄"，把 "What a fascinating topic" 等逐字记了 20 条，
  关键数字仍漏——**单靠 prompt 改不动模型的提取行为**，正则补充层才是可靠的解法。

## 四、验证结果（2026-11-22）

**单案例**：`8e91e7d9` 加数字补充后抓到 "3 sisters" + "a brother"，
答案从 3 → **4（正确）** ✓

**60 题 A/B**（basic vs 数字补充，同 seed 20261121，同模型同 prompt）：

| 口径 | basic | 数字补充 | 差 |
|---|---|---|---|
| 总分（60题） | 71.7% | 71.7% | 0 |
| **补充触及的 23 题** | 73.9% | **87.0%** | **+13.1pp** ✓ |
| 未触及的 37 题 | 70.3% | 62.2% | -8.1pp（模型自记随机波动） |
| multi-session (16题) | 56.3% | 62.5% | +6.2pp |

**关键解读**：总分持平是假象——
- 数字补充**只触及 23 题**（其余题没有"数字+名词"模式），这 23 题 **+13.1pp** 是真实收益；
- 未触及的 37 题退步 8.1pp，但这批题数字补充根本没介入，差异来自**模型自记的随机性**
  （同 prompt 每次记的内容不同），不应归咎于补充层；
- 逐题看：修对 4 题（3 题有数字补充，含"siblings=4"）、弄坏 4 题（**全部 nums=0**，补充未介入）。

**结论**：数字补充层对被触及题是**净正收益（+13pp）**，机制正确（逐字补回句中数字），
采纳为可选增强（ `--num-supplement`）。样本 23 题偏小，若要设为默认建议全量验证。

15 项 temporal memory 测试通过（含数字兜底专项）。

## 五、诚实边界

- 正则补充只覆盖"数字+名词"这类可枚举模式，抽象事实仍靠模型自记。
- 补充的 "用户提到 3 sisters" 是模板句，不是自然语言提炼——但**逐字保留了关键数字**，
  对 QA 检索够用（评测验证中），产品化时可再优化措辞。
- 借鉴的是 AMBRACE 的思路与护栏，不是复制代码（两项目场景不同：中文角色扮演 vs 英文 QA）。

## 六、结论

数字补充层机制正确、对被触及题 +13.1pp，**采纳为可选增强**（`--num-supplement`）。
暂不设为默认：样本 23 题偏小，且总分被模型自记随机性抵消，若要默认需全量验证。
真正启示：**提升记忆写入质量，纯规则补充层比改 prompt 更可靠**——
增强 prompt 让模型记了 20 条寒暄仍漏数字，正则补充直接逐字抓回。

产物：`bench_results/mem-basic-numsupp/`、`bench_results/mem-basic-ctrl/`、`bench_results/numsupp-smoke/`。

## 七、全量验证（2026-11-22 续）—— 方法论修正

**重要**：不能用旧的 `lme-retrieval-full500/`（70.0%）直接比——那是 speaker 字段/助手话/
兜底逻辑改造**之前**的代码（其 tmem 无 speaker 字段）。中间公共代码改过多次，
拿它当对照会引入混淆变量。

**正确做法**：用**当前代码**跑两个全量对照，只差 `--num-supplement` 一个变量：
- `bench_results/lme-full-ctrl/`（当前代码，无补充）
- `bench_results/lme-full-numsupp/`（当前代码，有补充）

两组同 seed 20261121、全量 500 题、断点续跑。结果待填。

**教训**：A/B 对比必须是"同代码 + 单变量差异"。公共代码在两次实验间改动过时，
旧基线不可复用——这个错误差点让 60 题的结论建立在虚假可比性上。

### 全量结果（已出）—— 收益不显著，不设默认

| 口径 | ctrl（无补充） | numsupp | 差 |
|---|---|---|---|
| 总分 500 题 | 315/500=63.0% (CI 58.7-67.1) | 316/500=63.2% (CI 58.9-67.3) | +0.2pp |
| 触及的 145 题 | 75.9% | 82.1% | +9题 |
| 未触及的 355 题 | 57.7% | 55.5% | -8题（模型随机波动） |
| 修对/弄坏 | — | 46/45 | 净+1 |

**McNemar 检验**：全量 p=1.0000（不显著）；触及题 p=0.1078（方向对但不显著）。

**最终结论（诚实）**：全量**未能证明**数字补充有统计显著收益。60 题的 +13.1pp 是小样本假象——
全量下模型自记的随机波动（修对46/弄坏45）把信号淹没。**不设为默认**，保留 `--num-supplement`
可选开关。机制本身正确（单案例 siblings 3→4 修对了），但收益不足以成为默认配置。

**更深的启示**：这再次印证"模型自记的随机性"是当前最大噪声源——任何写入改造的收益
都被它淹没。真正要提升记忆质量，得先解决模型自记的不稳定性，而不是叠加规则补丁。
66 题/145 题的正向信号值得记，但不足以支撑默认化决策。

产物：`bench_results/lme-full-ctrl/`、`bench_results/lme-full-numsupp/`（各 500 题 + score）。
