# YoAi 任务自适应分支进化 · 实施排期（EVOLUTION-PLAN）

> 来源：用户设计单《YoAi · 任务自适应分支进化设计单》v0.1（2026-11-20）。
> 本文把设计单落成工程排期，并补上 UI 更新排期与"需共同设计"的决策点。
> 状态：**M0 开工中**；M1–M4 为规划，未实现。

## 1. 定位与边界

- 这是 **YoAi 外层能力**：进化档案、路由器、候选生成、评测系统全部在 YoAi 实现。
- **Core 保持通用、轻量、可扩展**，`src/yai_core/` 零改动；复用其事件流、OutcomeVerifier、
  Budget、DiagnosticEvent 作为证据来源，不侵入内核。
- 专家以"轻量能力配置"形式存在（见 §3），**人格与个人记忆共享、不随分支复制**。
- 目标不是让进化树无限生长，而是让 YoAi 越来越会判断"何时用哪种能力"。

## 3. 专家节点契约（待用户确认的假设）

这是 M0 的地基，我按以下默认实现，请拍板：

- **专家 = 轻量能力配置**，不是完整 `YoAiAgent` 实例。字段：工具白名单、策略偏好、提示词片段、
  model tier、预算、能力标签。**不含**个人记忆、人格、会话历史。
- **人格与记忆共享**：运行时由外层注入同一个 Context/Goals，专家只带"能力切面"。
- **恢复点（Checkpoint）** = 节点配置 + 工具清单 + 提示词 + 依赖版本 + 父节点 id + 证据索引；
  `restore()` 生成一个**新的 candidate 节点**（不复活 retired 节点），保留血统。
- **生命周期**：`candidate → probation → active → retired`，只允许向前迁移；retired 为终态但保留档案。
- **父节点产生子节点后仍可参与路由**（active 状态不变）。
- **版本**用全局递增整数；血统靠 `parent_id` 链表达，不假设单线继承。
- **样本隔离**：评测记录从 M0 起就带父节点 id + 样本指纹字段，M2/M4 直接消费，不后补。

## 4. 各阶段详述

### M0 · 进化档案（本次开工）
- `src/yoai/evolution/models.py`：`ExpertSpec` / `ExpertNode` / `Checkpoint` / 生命周期状态机。
- `src/yoai/evolution/archive.py`：`EvolutionArchive` —— 建根、生子、状态迁移、血统查询、
  恢复点、按能力标签筛选、JSON 原子写 + 损坏隔离。
- 验收：血统/状态机/恢复/跨会话持久化/损坏隔离全部离线测试通过。

### M1 · 节能路由（已实现骨架）
- `src/yoai/evolution/fingerprint.py`：任务指纹（NFKC 归一 + 中文单字/bigram + 能力标签 +
  结构信号 + 稳定 key），词典可注入、零依赖。
- `src/yoai/evolution/router.py`：`ExpertRouter` 一次匹配直接选中 active 专家，无可靠候选
  回退 active 根节点；产出可审计 `RouteDecision`（指纹/候选分数/理由/回退标记）。
- **两层边界**：Core 的 AdaptiveRouter 决定"怎么执行"（direct/react/plan/clarify），
  这里决定"谁执行"（哪个专家）；选定后仍由 Core 驱动。
- `max_performance` 模式留桩（明确 NotImplementedError，属 M3，不假装实现）。
- 验收：14 项测试通过（指纹稳定/标签命中/选中/回退/非 active 不参与/无根失败/决策可审计）。

### M2 · 证据门控进化（已实现）
- `src/yoai/evolution/candidate.py`：`CandidateGenerator` 基于归因 + 证据从**实际执行节点**
  派生候选；environment/none 不生成分支（避免无意义进化）；diff 记录改动理由。
- `src/yoai/evolution/promotion.py`：`PromotionGate` —— candidate→probation 用隔离评测
  （insufficient/regression 不晋升），probation→active 需试用样本达标且无失败，
  active 退化→retired（保留档案）。
- `src/yoai/evolution/engine.py`：`EvolutionEngine.evolve(evidence_id)` 编排归因→门控→候选→
  评测→晋升决策，产出可审计 `EvolutionReport` 并落证据库。
- **诚实实测**：谎称"已记住"未落盘 → verification=verified_failure → 归因 capability →
  生成候选（parent=实际执行节点）；但验证样本 0 条 → 评测 insufficient → **不晋升**，
  候选留 candidate。真实展示了"没通过独立验证就不晋升"。
- 验收：12 项测试通过（不进化场景/能力候选/路由标签/样本不足不晋升/改进晋升/退化保留/试用晋升/审计）。
- 边界：候选增强是朴素确定性规则（补工具/补标签/补提示），策略改写留未来；引擎不自动在
  每次对话后触发（避免分支泛滥），由宿主显式调用或低影响任务试用触发。

### M3 · 最高性能模式（规划）
- 少量候选低成本试跑，复用 Core `Budget`（模型/工具/token 三墙）限流，跑完即弃、不污染正式执行。
- 验收：预算触顶终止、试跑结果不写正式档案。

### M4 · 长期指标（规划）
- 真实任务试用 → 能力证据更新 → 长期指标（成功率、退化告警、能力边界）。
- 对照固定 Agent / 线性自进化 / 无自适应路由分支 Agent。
- 验收：真实用户使用一段时间后的趋势报告（无法开发期加速）。
