## 1. 本意（项目所有者（你）的表述归纳）

RSI 进化**不是限制工具集**。每次进化在树上对应节点**长出新分支**，形成**足够差异化**的新节点，
并**登记它的能力偏好**；下次任务根据能力偏好**选中最合适的节点**执行。

三个关键词：**分支（不覆盖）**、**差异化（不是微调）**、**按偏好路由（学出来的，不是写死的）**。

## 3. 成熟方案参考

| 方案 | 做法 | 借鉴点 |
|---|---|---|
| **Darwin Gödel Machine**（Zhang, Hu, Lu, Lange, Clune，arXiv 2505.22954） | 维护一个智能体**档案库**；每次从档案里抽一个智能体，生成它的一个"新的、有意思的"变体，验证后加入档案，档案长成一棵**多样化的树**；并行探索多条路径，SWE-bench 20% → 50% | 与本意几乎一致：**所有变体都留档**、从任意节点（不只是最好的）长分支、强调**多样性**而不是只保留冠军 |
| **Quality-Diversity / MAP-Elites**（DGM 作者 Clune 的经典方向） | 按"行为特征"把解空间分成格子，**每个格子只保留一个精英**；新解要么占领新格子，要么打败格子里的旧精英 | 给"足够差异化"一个**可执行的判据**：新节点必须落到新格子，或在同一格子里更强 |
| **Symphony-Coord**（arXiv 2602.00966） | 把"选哪个智能体执行"当作**在线多臂老虎机**，分工从交互和反馈里自然形成，不靠固定的任务→角色映射 | 能力偏好**从反馈里学**，而不是写死在标签里 |
| **REDEREF**（arXiv 2603.13256） | 用 **Thompson 采样**按历史贡献选择被委派的智能体，用**带记忆的先验**减少冷启动；比随机委派省 28% token、快 19% | 新节点继承父节点的先验 → 冷启动不必从零试错 |

## 4. 新模型

### 4.1 节点"基因"：可变异的维度（工具只能"偏好"，不能"删除"）

| 维度 | 取值 / 例子 | 说明 |
|---|---|---|
| `strategy_bias` | direct / react / plan / clarify | 已有 |
| `method` | 方法论片段，例如"先列假设再动手""先查记忆再回答""写完自检一遍" | 替代现在的单句 `prompt_suffix` |
| `tool_preference` | 优先使用的工具 + 使用提示，例如"涉及时间先调 `now`" | **只影响提示和排序，不裁工具表** |
| `verify` | off / self_check / state_assert | 收尾是否自检（对应现有 OutcomeVerifier） |
| `memory_policy` | 不查 / 先查事实 / 先查事件时间线 | |
| `model_tier` / `budget` | standard / strong；最大步数 | 已有 |

`ExpertSpec.tools` 保留字段以兼容旧档案，**语义改为 `tool_preference`**；`tool_filter` 白名单只留给评测脚本。

### 4.2 差异化判据（MAP-Elites 式格子）

- **行为描述子** = (`strategy_bias`, `verify`, `memory_policy`, `model_tier`, 主偏好工具族)。
- 新候选的描述子与**父节点和所有兄弟节点**比较：
  - 至少 **2 个维度不同** → 视为新格子，允许长出；
  - 与某个已有节点同格 → 只有在**同一能力标签上验证显著更好**（沿用 R2.2 隔离验证）才替换为该格精英，旧精英转 retired（留档）；
  - 否则拒绝，理由写进进化报告（"与 X 节点同质"）。
- 一次变异最多改 2 个维度（保留"一次只改一点、可归因"的原则，同时保证有足够差异）。

### 4.3 能力偏好登记（学出来的画像）

每个节点维护 `CapabilityProfile`，按**能力标签**累计：

| 字段 | 来源 |
|---|---|
| `n` / `wins` | 证据里 `verification.status == verified_success` 计为 win；`verified_failure` 计为 loss；`not_verifiable` 不计 |
| `feedback` | R0 信号：重新生成 / 撤回 = 负，复制 / 分享 = 正（权重小于验证结果） |
| `cost` / `latency` | 证据里的 usage 与耗时（中位数） |
| 后验 | Beta(α=1+wins, β=1+losses) |

- **冷启动**：新节点继承父节点在同一标签上的后验，但**打折**（例如 α、β 各乘 0.3），
  并在**它被长出来要解决的那个标签**上加一点乐观先验——对应 REDEREF 的"带记忆的先验"。
- 静态 `capability_tags` 降级为**先验**：只决定"谁有资格参与这个标签的竞争"，不再决定"谁赢"。

### 4.4 路由：Thompson 采样

1. 任务指纹 → 标签集合（沿用 `fingerprint`）；
2. 候选 = 该标签下所有 active 节点（+ R3.2 试用中的 probation 节点）；
3. 每个候选按标签采样 θ ~ Beta(α, β)，取平均，减去成本惩罚 λ·cost；
4. 选最大者；**没有候选或证据极少时回退根节点**（保持现有语义）；
5. 安全阀：
   - 探索比例上限（例如 ≤ 10% 的任务给"非当前最优"节点）；
   - 带写操作 / 高风险标签的任务**只用当前最优**，不探索；
   - `RouteDecision` 记录采样值与理由，保持可审计。

### 4.5 生长循环（复用现有 R0–R5，不推翻）

```
真实任务 → 证据 + 反馈（R0）
   → 画像更新（新）
   → 边界看板发现弱标签（R1）
   → 触发：样本 ≥ 20 且 weak，7 天冷却（R2.1，保留）
   → 从"该标签上表现最好的节点"长分支：按 4.1 变异 ≤2 维（新）
   → 差异化判据（新）
   → 隔离验证（R2.2）→ probation（R3.1）→ 试用路由（R3.2）
   → 人工批准 → active（硬条件不变）→ 回归监控 / 回滚（R3.3）
```

DGM 的另一个要点保留：**retired 节点也留在档案里**，以后可以作为"垫脚石"再长分支。

### 4.6 变异由谁提出

- 第一阶段：**确定性规则表**（例如"temporal 标签弱 → `memory_policy=先查时间线` + `tool_preference=now`"），可解释、可测试；
- 第二阶段：让模型按 JSON schema 提出变异，**再由规则校验**（维度合法、≤2 维、满足差异化判据）——模型只提议，不直接写档案。

## 5. 定时任务是 RSI 的好数据源

同一个定时任务每天用同一个 prompt 运行 → 天然的**低噪声重复样本**；
可以在 trial 期让同一个定时任务交替由父 / 子节点执行，做小样本对照，而不打扰日常对话。
（需在调度器 runner 里补证据采集，见 SCHEDULER-PLAN 第 15 节 S2 局限。）
