# 生产侧记忆写入保障 · 实施计划（#2）

> 2026-11-23 立项。用户在计划台账选做 #2，先出计划、不实施。

## 一、问题（为什么需要）

生产侧目前**只有一条记忆写入路径**：模型在主对话 loop 里自愿调 `remember_event`。
实测风险：
- **批量回放场景**：模型自记会在"认真提炼（13-17条准确事实）"与"敷衍摘录（36条英文碎片）"间随机跳，
  一次跳到敷衍模式就漏关键事实（`SELF-MEMORY-STABILITY.md`，低温后 +8.8pp 是批量场景最优）
- **15 题样本**：6/15 题模型记 0 条（擅自改用 remember_fact 或判断无事实）
- **单轮场景**：触发率 10/10、事实准确、温度无差别（`SINGLE-TURN-MEMORY-FEASIBILITY.md`）——
  但这是探测专用 prompt 的结果，不能保证所有真实用户消息都触发
- **assistant 类弱项**：模型自记只记第1项漏第2项（Patagonia 记了/Southwest 漏了）

**核心判断**：记忆写入不能完全依赖模型自愿。需要一个**不依赖模型的确定性兜底**，
并让写入状态可观测——这样"记 0 条"不会再悄悄发生。

## 四、方案（分阶段，先小后大）

### 阶段 A：写入可观测（无行为改动，先做）
**目标**：在改任何写入逻辑前，先知道生产里到底发生了什么。

- A1. 定义写入事件计数：每次 `remember_event` 调用记一条轻量指标（不记内容，只记条数/时间/会话/触发方式）
- A2. 在 `YoAiAgent` 暴露 `last_write_stats`：本轮对话模型调了几次、写了几条、是否 0 条
- A3. 桌面端状态栏或调试面板显示"本轮记忆 +N 条"（可选，先日志）
- **验收**：跑几天真实对话，统计"记 0 条"的比例——这是后续所有改造的基线

### 阶段 B：确定性兜底接入（核心改造）
**目标**：模型不写时，规则兜底保证事实不丢。

- B1. 在 `YoAiAgent.astream()` 收集本轮 user/assistant 消息（从 task + Core 的 DONE 事件拿最终回复）
- B2. 任务完成后检查 `last_write_stats`：若为 0 条或低于阈值 → 调 `remember_from_transcript(turns)` 兜底
- B3. **关键护栏**（借鉴 AMBRACE，已在评测验证）：
  - 内容逐字取自原话，**不造句**
  - **严格胜出**：已有记忆里有的事实不重复写（避免兜底污染）
  - 改口不回灌旧值
- B4. 兜底触发与否、写了几条，计入 A1 指标（区分"模型写"vs"兜底写"）
- **验收**：构造"模型故意不调工具"的测试，确认兜底写入准确；跑已有测试套件

### 阶段 C：数字/结构化补充（可选，默认关）
- C1. 把 `supplement_number_facts()` 接成开关（复用评测的 `--num-supplement` 思路）
- C2. **不设默认**——全量 A/B 已证不显著，只在特定场景（数字密集对话）由用户/配置开启
- C3. 若将来模型调用成本不是约束，可考虑"小模型独立抽取"替代规则（见阶段 D）

### 阶段 D：独立抽取层（暂不做，记录方向）
- 生产侧目前没有独立记忆调用，加一层 = 多一次 LLM 请求（延迟+成本）
- 单轮验证显示收益为零；批量长历史才有明显收益
- 若未来产品形态变成"一次喂多轮历史"，再考虑启用；当前**不实施**

## 五、验证计划（等价性优先）

1. **单元测试**：兜底触发条件、内容逐字、去重、不重复写——每条一个测试
2. **集成测试**：DemoModel 跑一轮对话，断言"模型记0条→兜底写入N条且内容来自原话"
3. **真实对话 A/B**（需用户配合）：同批真实对话跑两周，对比开启/关闭兜底的"记0条率"和人工抽查准确率
4. **不变量**：开启兜底后，`TemporalMemory` 的既有工具行为（events_between / facts_by_tag / timeline）不变

## 六、风险与护栏

- **重复写入**：模型写了大部分、兜底又补一遍 → B3 严格胜出去重
- **噪音污染**：兜底规则抓到无关数字（如"2026年"当事实）→ 复用已验证的名词白名单，不扩规则
- **改口问题**：用户先说"3只猫"后说"养了狗" → 改口不回灌旧值（AMBRACE 护栏）
- **多消息并发**：桌面端当前单 worker 串行，无并发写竞争；若未来开并发需先给 `_save` 加锁（见"桌面端并发档位评估后撤销"）
