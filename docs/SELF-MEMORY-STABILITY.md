# 模型自记稳定性 · 立项与验证

> 2026-11-22 单独立项。这是多轮探索（记忆层 / 进化接线 / 写入改造）共同指向的真瓶颈：
> **模型自记的随机性淹没了一切写入改造的收益**（全量修对46/弄坏45，McNemar p=1.0）。

## 一、问题量化（实测）

实验：`bench/probe_selfmemory_variance.py`，同 5 题各跑 3 次记忆阶段，比较条数与内容。

### 默认温度（网关默认，未设 temperature）
```
题1 counts=[36, 17, 13]   题2 [15, 24, 12]   题3 [11, 14, 16]
题4 [25, 20, 12]   题5 [8, 10, 7]
条数标准差 4.70
```
**逐条看内容发现关键现象**：模型在两种模式间随机切换——
- **认真提炼模式**（题1 run1/2）：13-17 条中文提炼，事实准确完整
  （3/15保养、32mpg、Shell积分、50000积分换$500礼品卡、3/22 GPS维修）；
- **敷衍摘录模式**（题1 run0）：36 条英文碎片（"Yup, that makes sense"）+ 数字补充，
  没提炼、混入噪音。

### temperature=0.1（借鉴 AMBRACE extractor.py:582）
```
题1 [14, 13, 12]  题2 [15, 15, 14]  题3 [13, 14, 16]  题4 [25,18,17]  题5 [9,5,8]
条数标准差 4.05（↓）
```
**三次全部稳定在"认真提炼模式"**：记的是同一批事实，措辞高度一致。
字面 Jaccard 从 0.004→0.026（提升但仍低，因同一事实中英文措辞不同，字面重合天然低——
**这个指标低估了真实稳定性**，逐条内容才是证据）。

## 二、根因

1. **网关未设 temperature** → 默认采样温度高 → 模型在"认真/敷衍"两种生成策略间随机跳。
2. 这是**生成策略的不稳定**，不是事实提取能力的缺失——同一模型在认真模式下提取质量很好。
3. AMBRACE 的经验直接印证：`extractor.py:582` 记忆抽取固定 `temperature=0.1`。

## 三、方案（按优先级）

### 方案 A：记忆阶段固定低 temperature（最小、最可能有效）
- 记忆阶段用 `SuanliAdapter(temperature=0.1)`，答题阶段保持默认；
- 生产侧：YoAiAgent 的记忆写入服务固定低温；评测侧：`--memory-temperature 0.1`。
- 已经在 `suanli_adapter.py` 加了可选 `temperature` 参数（默认 None 不改行为）。

### 方案 B：确定性为主 + 模型只做补充（更彻底，工作量大）
- 规则/正则抽取可枚举事实（数字、名字、日期）——已验证机制正确；
- 模型只在低温下补抽象事实，且输出需逐字依据校验（借鉴 AMBRACE fallback 护栏）。

### 方案 C：多次采样投票/取并集（成本换稳定，额度无限可用）
- 低温跑 2-3 次取并集，覆盖率最高；但需解决措辞归一与去重。

## 四、验证计划

1. **单变量 A/B**：当前代码 + 只改记忆阶段 temperature（默认 vs 0.1），
   全量 500 题同 seed 对照，McNemar 检验。
2. **稳定性复测**：低温配置下重跑 probe，确认稳定在认真模式。
3. 若 temperature 显著改善 → 设为记忆阶段默认；若不显著 → 如实记录，转方案 B/C。

## 四·补 全量 A/B 结果 —— 显著收益，找到根因

- `SuanliAdapter` 加可选 `temperature` 参数（默认 None 不传字段，向后兼容）。
- 评测适配器加 `--memory-temperature`（只作用于记忆阶段，答题阶段不变）。
- **全量 A/B（同代码单变量，500 题）**：

| 口径 | 对照（默认温度） | 低温 0.1 | 差 |
|---|---|---|---|
| 总分 | 315/500 = **63.0%** (CI 58.7-67.1) | 359/500 = **71.8%** (CI 67.7-75.6) | **+8.8pp** |
| multi-session | 46.6% | 60.2% | +13.5pp |
| temporal | 68.4% | 79.0% | +10.5pp |
| knowledge-update | 56.4% | 73.1% | +16.7pp |
| assistant | 46.4% | 48.2% | +1.8pp |
| user | 91.4% | 88.6% | -2.9pp |

**McNemar p=0.000054（极显著）**：修对 80 / 弄坏 36，净 +44 题。
平均记忆条数 15→13（低温更精炼，非更多）。

**结论**：找到了真瓶颈根因——**网关默认温度让模型自记在"认真提炼"与"敷衍摘录"间随机切换**。
固定 temperature=0.1 后稳定在认真模式，依赖记忆质量的题型（multi/temporal/knowledge）
涨幅最大，符合机制。**这是多轮探索以来第一个统计显著的提升。**

**处理**：
- 评测侧：`--memory-temperature 0.1` 作为记忆阶段默认配置（后续评测都带此参数）。
- 生产侧：**不擅自改默认**——生产对话的自然度与评测刷分诉求不同，低温可能让回答死板；
  记录为可选项，待产品侧评估。诚实区分评测优化与生产行为。
- 数字补充（+0.2pp 不显著）与低温（+8.8pp 显著）对比，再次证明：
  **解决自记稳定性 >> 叠加规则补丁**。

## 五、诚实边界

- temperature=0.1 不改"敷衍模式为何出现"的根因，只是压低采样随机性；
  若某些题仍跳到敷衍模式，需方案 B/C。
- judge 仍是 deepseek 非官方 gpt-4o，不可与榜单直接比（全程口径一致）。
- 所有改动在 YoAi 内，原 Core 零改动。
